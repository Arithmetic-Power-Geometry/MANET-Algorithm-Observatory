# MANET Routing Evidence Atlas — Application Architecture

## Scholarly purpose

The Streamlit application is an interactive companion to the versioned evidence repository. It is not an alternative source of results and does not contain manually maintained scientific claims that diverge from the underlying CSV registries.

## Design principle

**One evidence base → repository analyses → paper artifacts + interactive atlas.**

## Academic views

1. Evidence Atlas — field-level orientation and research status.
2. Algorithm Explorer — mechanism, information, capability, cost, evidence and limitations.
3. Evidence Explorer — study registry and V3+ structured claims.
4. Benchmark Observatory — implementation provenance, smoke gates, scenario and metric contracts, later results/frontiers.
5. Gaps & Obligations — typed gaps and falsifiable research obligations.
6. Methodology — V/C/E/G vocabularies and population boundary.
7. Reproducibility — transparent readiness and pending-work state.

## Future views after evidence exists

- causal evolution timeline;
- routing decision cube;
- evidence maturity heatmap;
- evaluation-space coverage matrix;
- contradiction network;
- ranking-stability surface;
- Pareto explorer;
- failure-frontier explorer;
- study-to-claim provenance drill-down;
- downloadable machine-readable filtered evidence.

These views must be generated only when their underlying data exists.

## Paper relationship

The app should be cited/described as a companion evidence interface only after:
- the evidence release is frozen;
- app outputs correspond to that release/tag;
- the public deployment is stable;
- archival provenance is available.

The paper must remain understandable without using the app.
