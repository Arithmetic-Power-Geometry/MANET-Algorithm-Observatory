# Canonical Visual Language

All paper figures should use a consistent grammar so readers learn the visual system once.

## Shapes
- circle: routing decision
- rounded rectangle: mechanism
- hexagon: required information/resource
- diamond: condition or frontier
- document node: evidence
- warning node: unresolved obligation

## Evidence encodings
Use labels/patterns that remain interpretable in grayscale:
- E0–E2: definition/basic simulation
- E3–E5: reproducible/robust/generalization evidence
- E6–E8: testbed/field/independent replication

## Gap encodings
Always print the textual code with any graphical encoding:
G-LIT, G-REP, G-EVAL, G-CONTRA, G-ROB, G-GEN, G-COST, G-REAL, G-CAP.

## Figure design rules
- one research question per figure;
- readable at final two-column size;
- no decorative 3-D charts;
- no unexplained acronyms;
- uncertainty shown where quantitative;
- literature evidence visually distinct from Observatory-controlled evidence;
- conditions visible on every performance/frontier plot;
- captions state the takeaway and evidence boundary.

## Flagship cover-style figure

The central visual should be a **MANET Routing Evidence Compass**:

center: routing decision

ring 1: mechanism families

ring 2: information/cost requirements

ring 3: evidence maturity

ring 4: operating conditions

outer ring: unresolved obligations/failure frontiers

The compass is navigation, not a ranking.
